# gpt-image-2（引擎代号 PRISM-I2）

文生图 / 图生图模型，指令遵循能力强，适合复杂构图和精确文字排版需求。

`--model` 传的值就是 `gpt-image-2`，逐字符照抄。

## 参数

`--prompt` / `--prompt-file` 之外的参数走 `--config`（JSON）。

| 参数 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| `aspectRatio` | string | 否 | `auto` | 见下方比例表，决定输出像素尺寸 |
| `images` | string[] | 否 | — | 参考图公网 URL 数组，传了就是图生图；最多 **8 张** |

没有 `size` 参数 —— 尺寸完全由 `aspectRatio` 决定，传具体像素值不会生效。
没有 `quality` 开关，平台固定用最高质量档，不需要也不能调。

## aspectRatio 对照表

| 值 | 输出像素 | 值 | 输出像素 |
|----|----------|----|----------|
| `auto` | 由 prompt 内容自动判断 | `3:2` | 1536 x 1024 |
| `1:1` | 1024 x 1024 | `2:3` | 1024 x 1536 |
| `16:9` | 1672 x 941 | `5:4` | 1408 x 1120 |
| `9:16` | 941 x 1672 | `4:5` | 1120 x 1408 |
| `4:3` | 1443 x 1090 | `21:9` | 1920 x 832 |
| `3:4` | 1090 x 1443 | `9:21` | 832 x 1920 |
| `2:1` | 1792 x 896 | `1:2` | 896 x 1792 |

`16:9` 出来是 1672x941，不是标准 1920x1080；需要标准分辨率自己再缩放一次。

## 用法

### 文生图

```bash
node bin/okflow.mjs generate \
  --model gpt-image-2 \
  --prompt "一杯冒着热气的咖啡放在木桌上，晨光从左侧窗户照入" \
  --config '{"aspectRatio":"16:9"}' \
  --wait
```

通常 1-3 分钟出图，`--wait` 不用加长超时。

### 图生图

把参考图公网 URL 塞进 `images` 数组即可，最多 8 张，图片必须是公网可访问地址，
本地文件路径不行（先传到能公网访问的地方，比如先跑一次文生图拿到 URL 再引用）：

```bash
node bin/okflow.mjs generate \
  --model gpt-image-2 \
  --prompt "把这张照片的风格改成水彩画" \
  --config '{"aspectRatio":"1:1","images":["https://example.com/ref1.jpg"]}' \
  --wait
```

prompt 较长时用 `--prompt-file` + `--config-file` 分开传，避免命令行转义问题。

## 写 prompt

按「主体 → 构图 → 光线 → 材质 → 色调」的顺序描述效果最稳定。需要给文字或 UI
元素留白时，直接在 prompt 里说明「画面右侧留白区域」，比生成后裁切更可靠。

避开审核雷区（命中会导致任务快速 failed，且 `errorMessage` 通常为空）：

- 人物用通用描述，不要具体人名、明星名、动漫角色名
- 不要点名品牌 logo、商标
- 不要用听起来像已有 IP 的专有名词

失败特征：提交成功拿到 taskId，但明显早于正常生成耗时就变 failed，且错误信息为空。
这种情况直接换 prompt 重试，不要怀疑参数配错。
